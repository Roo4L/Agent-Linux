# Code Quality Review — v0.4.0 Rust Rewrite (PR #59)

**Scope** `rust/` (17.3 kLOC), `packaging/curl-installer/`, `plugin/catalog/`, `scripts/`, `tests/`, `.github/workflows/`. Website excluded.
**Method** 15 read-only reviewer agents across five traits; every headline claim below re-verified by hand.
**Snapshot** `3515c7c`. `cargo test --workspace` — 375 pass, 2.6 s.

---

## Verdict

| Trait | State | The one thing |
|---|---|---|
| **Readability** | Structure good, surface lying | ~300 comment citations point at files this PR deleted; four comments assert the *opposite* of adjacent code |
| **Simplicity** | Mostly earned | Six byte-identical copies of one projection; twelve expired `allow(dead_code)` hiding four dead modules |
| **Testability** | Bimodal — pure core exemplary, privileged half unreachable | At least six tests pass while asserting nothing, or self-disable on a provisioned host |
| **Reliability** | Weakest trait | Recipe dispatch and every package-manager call are unbounded; two data-loss paths inside the *idempotency* helper |
| **Security** | Strong perimeter, soft interior | Sudo hop and sudoers are exemplary; three symlink-follow primitives hand root's authority to the agent user |

**The through-line: the Rust is better than its tests and its comments.** Module boundaries, the pure-core split, `sysio::write_file_atomic`, the sudoers TOCTOU belt and the argv discipline are genuinely well-built. The damage clusters in three seams the cutover left behind — a comment layer still describing the pre-cutover world, a privileged half with no injection points (so its tests became decorative), and unbounded I/O on the paths that mutate a real machine.

**Merge posture:** the logic is sound enough to ship; the *release path* is not. Items 1–4 below are pre-merge.

## Readability

**Verdict: the code reads well; the commentary does not.** Naming, module decomposition and control flow are consistently good — `provision/probe.rs`, `provision/wizard.rs`, `classify.rs` and `reuse.rs` are files you can answer all five orientation questions about in under a minute. What fails is the layer meant to explain *why*: it was written against a codebase that no longer exists, and it was not updated when the cutover landed.

- **~300 dangling citations.** 189 in the core + top-level modules, ~127 in `cmd/`+`provision/`, ~12 on the shell surface. These are the *load-bearing* comments, not decoration: `detect_gates.rs:294` justifies the `adoptable` formula as "mirrors detect.ts:266-273". The reader hits a dead end exactly where the code is subtle — and once trained to skip citations, they skip the correct rationale sitting in the same comment. Internally inconsistent too: `install.rs:13` and `:430` attribute the same behaviour to two different deleted files.
- **Four comments assert the opposite of the code.** `main.rs:179` says `install`/`remove`/`upgrade` are "loud EX_SOFTWARE(70) not-implemented stubs" — `cmd/install.rs` is 833 lines with no `EX_SOFTWARE`. `dispatcher.rs:27-32` warns the CLI-05 EUID guard "has no Rust home yet" and MUST be ported — `guard.rs` implements it and `main.rs:199` calls it before every verb, so the file owning the sudo hop documents a false security model. `cmd/provision.rs:331` calls `--purge` a "structural stub" returning 0 — `run_purge` runs uninstall recipes, `remove_dir_all("/opt/agentlinux")`, deletes four `/etc` files and `userdel -r`s the user. `remediate_npm_prefix.rs:23` says its path "is not exercised by the live provisioner yet", directly above a Security paragraph — it is reachable via `cmd/provision.rs:466`.
- **A private vocabulary that resolves nowhere.** 172 occurrences of "Pitfall 4", "T-56-06", "Wave-1/2", "Plan 03", "RESEARCH §Pattern 1". These resolve only inside `.planning/`, which `AGENTS.md` declares is *not documentation*. `detect_gates.rs:150` defers the reason for its trickiest predicate choice to "Pitfall 5".
- **Four definitions of "the agent's home".** `main.rs:150` honours `$AGENTLINUX_AGENT_HOME`; `recipe_env.rs:152` ignores it; `npm.rs:119`/`:173` inline the literal; `probe.rs:33` hardcodes `/home/agent`. No rule is recoverable from any one file. (This is also finding 5 under Security.)
- **Boolean-blind signatures at the two most consequential switches.** `as_user(…, stream: bool, …)` maps a timeout to exit **124** streamed and exit **1** buffered (`dispatcher.rs:204` vs `:272`); call sites pass a bare `false`. `load_catalog(dir, true/false)` is "validate the schema" — the difference between a mutation path and a report path.
- **Twelve file-scope `#![allow(dead_code)]`** whose stated justification ("until Plan 02/03 lands") expired. They now suppress the signal that would have caught four genuinely dead modules for free.

*Reads well:* `provision/probe.rs` (one enum per host question, each variant documenting the decision it implies); `provision/wizard.rs`; `sysio.rs`'s `TmpGuard` + `write_file_atomic`; `reuse.rs:64-108`; `provision/registry_cli.rs:48-94`, whose three-tier precedence doc names the failure each tier prevents — a model WHY comment; `scripts/check-version-lockstep.sh`.

## Simplicity

**Verdict: the big architectural calls are right; the small ones repeat themselves.** The core/binary split, `TAG_PRECEDENCE` as an ordered slice with a comment explaining why it is *not* a map, clap-derive over hand-rolled help, and fn-pointer DI over trait objects are all correctly sized. One headline correction to an assumption worth recording: **`semver_shim.rs` is not a hand-rolled semver implementation.** Of its 703 lines only 185 are code, every one delegating to the `semver` crate; it is a ~120-line adapter for two node-semver divergences named in advance in `docs/research/stack-reconsideration.md:225`. Justified and cheap.

- **`to_core_entry` exists six times, byte-identical** (`install.rs:487`, `upgrade.rs:420`, `list.rs:79`, `pin.rs:32`, `adopt.rs:45`, `npm.rs:215`) — each a `serde_json` round-trip to copy seven plain fields. The stated rationale ("field names stay in lockstep") is **inverted**: a struct literal makes a rename a compile error; the round-trip makes it a runtime panic in production. `list.rs:93` already does it correctly one screen away.
- **`chown_by_name` exists seven times** (four md5-identical), and `registry_cli.rs:366` *documents* the duplication — "mirrors `sysio::resolve_owner`, which is private to that module" — rather than fixing it. Also triplicated: `format_epoch_utc` (only the `adopt` copy is tested), `build_env` + `recipe_path`, `real_dispatch`, `create_if_absent_0644`.
- **`schema_gen.rs` produces an artifact nothing validates.** `schema_json()`'s only caller is its own drift test. Its comment points the negative-case teeth at `plugin/cli/test/schema.test.ts` and the `cli-unit` job — both deleted by this PR. **No JSON-Schema validation of `catalog.json` happens anywhere in the repo**; the real gate is a 20-line hand-transcribed jq mirror. Either delete the codegen or add a test that validates the live catalog against it.
- **Four dead modules/functions**, invisible because of the expired `allow(dead_code)`: `probe.rs` (77 lines *with tests*, zero callers — while `cmd/list.rs:107` reimplements it inline, untested); `dispatch_recipe_with_env`, whose doc admits it exists "so `full_child_env` has a non-test consumer"; `Resolutions::seed_create`; `cache::read_detected_agent`.
- **`Resolutions::agents` is computed on every real run and read once** — by a `--dry-run` printer that then calls `emit_report`, which *re-runs the identical probe+gate loop* and prints the same decisions in a different format.
- **Test-suite shape:** five hosted-MCP bats files, ~700 lines, differ in four semantic values. The repo already solved this — `53-catalog-npm-cluster.bats:111` drives five tools through one `_agent_lifecycle` helper. Same for six MCP recipe pairs whose uninstalls differ only in a server id.

*Correct call:* deleting `tests/harness/` and `tests/mutation/`. `bash-mutator.sh` implemented none of the five mutations its header claimed — it printed a message and `exit 0` — and `60-mutation-scaffolding.bats` asserted that this always-green stub existed *and that the nightly workflow had `continue-on-error: true`*: a gate testing that a gate is disabled. The one real check in there (HRN-07 codex-agent sync) is covered by the pre-commit hook.

## Testability

**Verdict: 375 green tests overstate what is defended.** `agentlinux-core` is genuinely pure — zero `std::fs`/`process`/`env` outside `#[cfg(test)]`, `BTreeMap` everywhere iteration order matters, and a real `cargo mutants` merge gate. But the split is drawn at the wrong *altitude*: the core holds leaf predicates while every policy decision — step ordering, branch selection, argv construction, guard composition — lives in the binary interleaved with the I/O that acts on it. The binary has no seams, so its tests could not be written honestly, and several were written dishonestly instead.

- **Tests that pass if you delete the code under test.** `sudoers.rs:316` builds a `ProvisionCtx` and asserts `matches!(ctx.resolutions.sudoers, Resolution::Bail)` — the value it just wrote; it never calls `run`. `cmd/install.rs:815` `literal_bytes_are_exact` re-`format!`s the marker strings *inside the test* and asserts them against literals — it passes if `install_with` prints nothing. `recipe_env.rs:258` re-types the production parse loop and asserts on its own copy. `remediate_npm_prefix.rs:499` re-types the body of `apply_rebase`. `category.rs:290`, labelled "the property form of Pitfall 3", recomputes `expected` from the same `TAG_PRECEDENCE` constant — reorder the table and the tautology follows it.
- **Tests that vanish on the target environment.** `guard.rs:142`,`:151` and `recipe_env.rs:253` wrap their entire bodies in `if !Path::new("/etc/agentlinux.env").exists()` — the file AgentLinux itself installs. On a provisioned host, and in the Docker containers after `provision` runs, they are empty and green. `probe.rs:250` and `cmd/provision.rs:901` guard `user_adoptable`'s only positive assertion behind `uid >= 1000`, which fails on a root CI runner.
- **The privileged surface is untested, module by module.** `provision/mod.rs`: zero tests. `cmd/provision.rs`: 754 lines, 12 tests, all flag validators. `install_or_overwrite` — the pre-install `visudo -cf` gate, the atomic 0440 install, and the post-install TOCTOU re-verify — has no test at all. Nor does `sysio::visudo_validate`. Nor does `resolve_argv`, whose `--` terminator and `-E`/`env_clear` coupling the module doc calls load-bearing; its one sudo-branch test asserts only `exit_code != 0` against a nonexistent user, which any failure satisfies.
- **The mutation gate covers 22% of the code and 0% of the privilege logic.** Both the merge gate and the nightly scope to `--package agentlinux-core`. `--in-diff` is additionally path-scoped, so a PR touching only the bin crate produces zero mutants and passes vacuously. Delete-the-function mutants that survive today include `install_or_overwrite`, `resolve_argv`, `effective_username`, and `Resolution::from_decision`.
- **Property tests are mostly decorative.** Six of seven assert only totality or determinism (`let _ = f(x)`; "the return is one of three enum variants" — which the type system already guarantees). The two with teeth verify membership and soundness but **never maximality** — a `max_satisfying` returning the *first* satisfying candidate passes both. That is precisely the defect `c44b858` fixed by hand. Generators are narrow too: `version_str()` emits `\d{1,2}\.\d{1,2}\.\d{1,2}` only, so the prerelease-ordering rules that motivate the shim's existence are never crossed.
- **Env-as-DI forces a hand-maintained global lock**, and two tests break it: `catalog.rs:473` and `guard.rs:141`,`:150` mutate process env without `env_guard()` while five other modules hold it. Tests also `clear_env()` *after* the assertion, so a failure leaks vars into whatever runs next.

**Coverage lost in the port.** The bats suite went 366 → 242 `@test`s. Some of that is legitimate — the EL-01 distro matrix, the apt/dnf argv shapes, REUSE-03 agent decisions and the npm-prefix strategy helpers all moved into Rust unit tests cleanly, and `pkg.rs:394` compares against literal expected argv rather than the function's own output. But these have **no successor anywhere**: the whole DET-01/02/03/05/06 detection and renderer contract (`15-detection.bats`, 25 tests — including "detection writes zero bytes to `/etc /home /usr/local/bin /opt`" and the `NO_COLOR` behaviour, a token that no longer appears in the repo); REUSE-02 Node reuse; four of REUSE-01's five predicates — `probe.rs:78` concedes it checks the shell only, so a brownfield `agent` with a root-owned home is now classified `Conforming` → REUSE; EL-07's three-way EL9 Node classification; and the `visudo`-rejects-tmpfile refusal, whose deleted test left behind a comment at `14-remediate.bats:528` reading "visudo-fail gate **UPHELD**" above no code.

*Designed well:* `provision/wizard.rs`'s `*_io<R: BufRead, W: Write>` seam is the best code in the review — TTY consent flows tested with in-memory cursors, no PTY, including the single-byte-then-drain injection mitigation. `npm.rs`'s `NpmDispatcher` and `cmd/upgrade.rs`'s `UpgradeDeps` are the model the rest should copy. `distro.rs` is fully substitutable. `sysio.rs`'s file half asserts idempotency by running twice. `semver_shim` P4c and `divergence` P3 verify soundness through `semver::VersionReq` directly, avoiding the circular-oracle trap.

## Reliability

**Verdict: the weakest trait, and the failures are on the paths that touch a real machine.** The primitives are good; the orchestration around them is not defensive.

- **Nothing that matters is time-bounded.** `dispatch_recipe` hardcodes `None` — every `install`/`remove`/`upgrade` and the purge uninstall. `PkgCmd::run` is a bare `Command::status()` with inherited stdio: no timeout *and* the child can read the installer's own stdin under `curl | bash`. Not one `curl` in the repo carries `--max-time` or `--retry`. A nightly `upgrade` timer behind a black-holed npm socket never completes and logs nothing past the first entry.
- **The timeouts that do exist are defeatable.** `escalate_kill` signals only the direct child (documented at `dispatcher.rs:313`), so grandchildren reparent to init — and the reader threads then block in `recv()` until *every* holder of the pipe closes it. The stated 30 s bound on `npm ls` is 30 s + ∞. It also means "timed out" stops the wait, not the work: a retry races the orphan over the same npm prefix, and `--purge`'s `pkill`/sleep-1/`userdel -r` sequence becomes non-deterministic.
- **Two data-loss paths inside the idempotency helper.** Covered as pre-merge item 4. The second one deserves restating: `strip_marker_block` has no unterminated-block detection, so a user who deletes the end marker while editing loses everything below it on the next converge run — data loss produced by the helper advertised as safe to re-run.
- **A wrong state reported as success.** `agent_user.rs` skips `locale_ensure` on the REUSE branch, and `user_state` classifies on shell alone. Run 1 creates the user then fails at locale → exit 70. Run 2 sees `Conforming` → REUSE → skips locale entirely → steps 20-50 pass → prints `agentlinux-install complete`, exit 0. `LANG`/`LC_ALL` are never enforced, violating BHV-01, and the installer says everything is fine. No per-step completion marker exists to prevent it.
- **The transcript misses everything worth reading.** `log::init()` runs *after* the DECIDE phase and after `flush_or_exit`, so a brownfield host refused non-interactively — the case most needing diagnosis — leaves the log absent or holding a previous run. Every step logs with bare `eprintln!`, so `[REMEDIATE-01]`, `[REUSE-WARN]`, the chown decision and the purge removals never reach the file; it holds ~8 orchestrator lines. And `init` opens with `truncate(true)`, so re-running to reproduce a failure destroys the failing run's transcript.
- **Errors arrive without context.** `write_file_atomic` propagates raw `io::Error`; the orchestrator adds only a step name. A failed step-40 reads `40-path-wiring step failed: No such file or directory (os error 2)` — which of four artefacts, on which operation, is unrecoverable without `strace`. Timeout logs name `sudo` (it is `argv[0]` on the drop path), never the agent or the recipe. `pkg.rs:381` prints the argv and discards the child's stderr, where apt explains itself.
- **Non-atomic replacement of the binary, the catalog, and the symlink.** `registry_cli.rs:280` does `remove_file` then `fs::copy` — the one module that does *not* use `write_file_atomic`, two files away. An interrupted re-provision leaves no `agentlinux` binary and a dangling symlink: strictly worse than before the run.
- **Sentinels are rename-atomic but not durable** (no `fsync`, no tmp cleanup), and one corrupt record fails `list_sentinels` for *every* agent — `rewire::reconcile_cross_wiring` then silently no-ops. Recovery is undiscoverable from the error text. There is also no `flock` anywhere: two concurrent `install`s race the same prefix.

*Robust:* `sysio::write_file_atomic` (same-dir tmp, `sync_all` before rename, mode before publication, RAII cleanup on every path including panic). `provision/sudoers.rs` layers `visudo -cf` before *and* after, both arms through one helper so create and remediate cannot diverge. `ensure_marker_block`'s strip-then-emit is correctly idempotent — the classic double-append bug is absent. DECIDE-then-ACT leaves a refused host byte-identical. `stdin(Stdio::null())` in the dispatcher closes the PTY-hang class this project has shipped twice. The QEMU harness's cleanup trap and its `selftest_checksum_guard` — proving on every run that the verification code rejects a flipped byte — are exemplary.

## Security

**Verdict: the perimeter is well-built and the interior assumes a trustworthy agent user.** That assumption is mostly fine under ADR-012, where the agent already holds `NOPASSWD: ALL` — but it fails in three states where the boundary is real: when the operator *declined* the sudoers remediation, in the window before step 20 runs, and after any future narrowing of ADR-012.

- **Three symlink-follow primitives give the agent user root's authority.** (a) `create_if_absent_0644` — pre-merge item 2, no race required, on the default path. (b) `ensure_marker_block` reads through a symlink as root and writes the *contents* into a file it then chowns to the user: plant `~/CLAUDE.md → /etc/shadow` and read it. (c) `write_file_atomic` calls path-based `set_permissions` on a tmpfile inside the user's own directory — swap it for a symlink between `sync_all` and `set_permissions` and chmod any file 0644. All three are fixed by `O_NOFOLLOW` + fchmod/fchown on the open handle, which `detect.rs:302` already does correctly.
- **`chown_recursive` can be walked out of the prefix.** The `lchown` is right, but the *recursion decision* uses path-based `symlink_metadata` then path-based `read_dir`. Swap `~/.npm-global/lib` for a symlink to `/etc` between them and every entry of `/etc` is chowned to the agent. Needs a dir-fd walk (`openat` + `O_NOFOLLOW|O_DIRECTORY`, `fchownat`).
- **`AGENTLINUX_USER=root` runs recipes as root** — pre-merge item 9. Relatedly, the CLI-05 guard compares two values both derived from the invoker, so its documented purpose ("bounds who can trigger a `sudo -u` recipe run") is not actually enforced.
- **`install_home` is `format!("/home/{user}")`, never the passwd home.** Adopt `bob` with home `/var/lib/bob` and the provisioner creates and populates a fresh `/home/bob`, writes `AGENTLINUX_AGENT_HOME=/home/bob` into `/etc/agentlinux.env`, and reports success — while every one of the six invocation modes silently gets nothing. This is also the upstream assumption the three symlink findings rest on, and nothing enforces it. `nix::unistd::User::from_name(user).dir` is already imported in the same tree.
- **Remediation silently widens a privilege scope.** `probe.rs:131` classifies any drop-in lacking the exact canonical line as `Drifted`; `--yes` then overwrites it with the blanket grant. An operator who deliberately narrowed the grant to specific commands has that narrowing reverted to `ALL` by a re-run, visible only as a generic `[REMEDIATE-03] action=overwrite`.
- **The `.sha256` sidecar is same-origin with the tarball** — a corruption check, not an authenticity check, and `install.sh` itself is served unsigned from the same GitHub account's `gh-pages`. Worth stating plainly rather than counting as a supply-chain win. `AGENTLINUX_RELEASE_BASE` is entirely unvalidated while `ORG` and `VERSION` are regex-gated, and its comment claims an HTTPS-only guard that does not exist.
- **`pr-preview.yml` publishes a branch's `install.sh` under `agentlinux.org`** — same origin, same cert, same brand, live until the PR closes. Fork PRs *cannot* reach it (the trigger is `pull_request`, so the token is read-only and the deploy 403s), so exposure is scoped to push-access holders. Still a near-perfect phishing artifact for a `curl | sudo bash` product.
- **Secrets are safe by prose, not by code.** `detect.rs:187` and `cmd/provision.rs:318` forward *every* `AGENTLINUX_*` var to children; the only thing stopping a future `AGENTLINUX_*TOKEN` is a comment saying it must not be. `catalog.rs:127` still deserializes `secret_env`, which ADR-017 forbids MCP entries from baking — unread today, but its presence invites re-wiring. `.gitleaks.toml` blanket-excludes `.planning/`, the tree where this workflow accumulates command transcripts.

*Well defended:* the sudo hop is correct — `env_clear()` then explicit pairs, so `-E` preserves an environment already reduced to nothing ambient; the `--` terminator is unconditional; **no path exists from catalog or CLI input into a shell string**, and the one `bash -c` in the provisioner interpolates a compile-time `&'static str`. `provision/sudoers.rs` satisfies the ADR-012 checklist exactly. `catalog.rs`'s `preserve_paths` traversal reject fails the whole load rather than dropping a row. `verify_binary`'s charset guard is genuine defence-in-depth. The MCP thin-installer rule is upheld *and tested* — `context7/install.sh:64` asserts the API key did **not** get baked in, a negative test on a secret. Release CI posture is sound: no `pull_request_target`, `contents: write` scoped to one job, pre-release tags publish with `make_latest: false`. Dependency surface: 75 crates, zero git deps, **no `unsafe` anywhere**.

## Method and caveats

- 15 reviewer agents, read-only, dispatched via `.claude/skills/review/` across four scope areas. All 15 completed (5 were relaunched after a session-limit interruption).
- Nothing was executed except `cargo test --workspace`. Reachability claims come from reading control flow. The reliability hang scenarios and the mutation-survival estimates are reasoned, not observed — worth one empirical check each.
- **The branch moved during the review.** `2aba062` and `3515c7c` landed mid-run; the latter already fixed a dead `run.sh` staging seam that an earlier reviewer had flagged. Findings are pinned to `3515c7c`. Note `cli.rs:25` still documents the `reuse-decision` subcommand that `3515c7c` removed — a fresh instance of the stale-comment class.
- Not covered: the ~25 catalog recipe suites were spot-checked, not read line by line; the deleted TypeScript unit suite (22 files, ~7 kLOC) was not mapped one-to-one against its successors, so further losses could hide in the registry-CLI half; branch protection and the collaborator set were not inspected.

Full findings with every citation: `CODE-QUALITY-REVIEW-APPENDIX.md`.
