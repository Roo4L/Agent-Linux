<objective>
Wave 1 — land the read-only / state-only verbs and the file adapters the whole
verb layer shares:

1. **The adapters** (bin I/O boundary): `guard.rs` (CLI-05 invoker guard),
   `catalog.rs` (full `CatalogEntry` load + preserve_paths traversal reject),
   `sentinel.rs` (atomic read/write/delete/list), `cache.rs` (the detect-cache
   reader deferred from Phase 55 → `DetectedAgent`, honoring
   `AGENTLINUX_DETECT_CACHE`).
2. **`list`** — the padded NAME/STATUS/CURATED/INSTALLED table (+ `--descriptions`,
   `--by-category` `## <label>` groups, `--json` Row array); the em-dash / ▸
   INSTALLED-column suffixes are load-bearing literals.
3. **`pin`** — state-only sentinel mutation via the ported `parse_pin_spec`; the
   `pinned to`/`pin cleared`/`follow upstream` literals; exit 64/1 map.
4. **`adopt`** — record reuse-eligible agents into sentinels (no install) via the
   ported `reuse_gate`/`remediate_gate`; the `[ADOPT]`/`[MIGRATE]` literals.

These three verbs consume the pure core (they never re-derive a decision) and
dispatch NO recipe (all recipe dispatch is Plan 03). Their parity is pinned by
the TS command unit tests + green 40-registry-cli.bats on the Rust build.

Purpose: prove the adapter + pure-gate + exact-stdout stack end-to-end on the
low-risk (no-subprocess) verbs first, and hand Plan 03 the shared adapters.
Output: the four adapters + three `cmd/*.rs` verb modules + `main.rs` routing.
The pure core is untouched.
</objective>
