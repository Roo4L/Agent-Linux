<objective>
Make plugin/catalog/schema.json a generated artifact of the Rust catalog types via schemars (TEST-03), with a CI drift-check that fails when the committed file differs from freshly-generated output — killing the two-artifacts-that-drift problem. Acceptance is FUNCTIONAL equivalence (ajv-strict passes, real catalog validates, all 12 schema.test.ts fixtures green including negatives), NOT byte-parity with the old hand-written schema.

Purpose: A single Rust source of truth for the catalog shape; a contributor who changes a type regenerates and commits, and CI enforces freshness. The three ajv consumers keep reading the same path, so nothing downstream changes behavior.

Output: schema_gen.rs (SchemaCatalogEntry + emitter + drift-check test), a regenerated plugin/catalog/schema.json, and a CONTRIBUTING note.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rust codegen -> schema.json -> ajv consumers | The one external touch this phase adds: schema-gen writes plugin/catalog/schema.json, which the shipped ajv validators + /opt staging consume. The risk is emitting a schema that silently ACCEPTS a malformed catalog entry (a dropped constraint). This boundary is guarded by the negative fixtures + ajv-strict gate, not by trust. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-54-03 | Tampering | generated schema.json drops a constraint | medium | mitigate | The generated schema must reject every negative schema.test.ts fixture (missing pin, bad source_kind, npm missing package name, lowercase secret_env, http endpoint_url, non-semver pin) AND validate the real catalog under ajv strict — the acceptance oracle is these fixtures + validate-catalog.mjs, so a schema that accepts malformed entries fails the gate (Pitfall 1). |
| T-54-04 | Spoofing | hand-edited schema.json diverging from the Rust SoT | low | mitigate | The drift-check #[test] fails CI when committed != generated; schema.json is marked generated via $comment so contributors regenerate rather than hand-edit. |
| T-54-05 | Denial of Service | ajv strict rejects the generated schema at CLI runtime | low | mitigate | validate-catalog.mjs (the exact ajv strict flags) runs as part of acceptance BEFORE commit; strict flags are NOT loosened to paper over a bad generation (Pitfall 2). |
