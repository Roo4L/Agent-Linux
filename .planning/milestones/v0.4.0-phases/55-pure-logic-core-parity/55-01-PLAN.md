    Add `pub fn valid(raw: &str) -> Option<String>` to `semver_shim.rs`. It is STRICT
    on partials (the A1 node-parity subtlety): trim, strip a single leading `v`/`V`,

    `semver.valid`: accepts prereleases, rejects partials and ranges.

    Add `pub fn satisfies(version: &str, node_range: &str) -> bool`. Parse the range via
    `VersionReq::parse(&normalize_range(node_range))` — reuse the existing `normalize_range`
    so the space→comma compound-range divergence is handled; on range parse error return
    `false` (never `Err`, never panic). Then lenient-parse the version via the existing
    `parse_lenient` (a cache version like `"v1.37.1"` must satisfy) and return
    `req.matches(&v)`; on version parse error return `false`. Route EVERY semver op through
    this module — do NOT add `semver::` calls to pin_spec/detect_gates later (anti-pattern
    in RESEARCH §Anti-Patterns; the whole TEST-04 isolation depends on it).

    exercise these two shapes, so they must be added here as the parity oracle boundary).
    Add a proptest: `satisfies(version, range)` is total (any inputs → a bool, never panics)
    and `valid(raw)` is total (any input → Some/None, never panics), mirroring the existing
    `proptests` module conventions (reuse `loose_version_str`/`range_str` from
    `proptest_strategies`).

    Keep the crate PURE — no `std::process`/`std::fs`/`std::env`. `valid` returning the
