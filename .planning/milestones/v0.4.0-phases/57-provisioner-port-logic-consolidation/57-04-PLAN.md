<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NodeSource CDN → `curl … setup_22.x | bash -` | Remote code executed as root to configure the repo; integrity = HTTPS + `curl -f` cert-verify + the GPG-signed repo (ADR-005). |
| npm prefix ownership → `npm install -g` (as agent) | If the prefix is root-owned, `npm install -g` hits EACCES or races root; the proactive agent-owned prefix + REMEDIATE-01 chown bound this. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-57-09 | Tampering | NodeSource curl-pipe-bash | high | mitigate | HTTPS + `curl -fsSL` cert-verify is the fetch-integrity control; ongoing integrity from the GPG-signed repo the setup script installs (ADR-005). Script-body SHA-256 is not published by NodeSource — accepted per ADR-005. The setup runs via the Phase-56 dispatcher (bounded exec), not an unbounded shell. |
| T-57-10 | Elevation | npm prefix ownership | medium | mitigate | The prefix is proactively created agent-owned (`ensure_dir … <user>:<user>`) so `npm install -g` never races root; REMEDIATE-01 `chown_or_rebase` corrects a drifted prefix behind the `--yes` gate. |
| T-57-11 | Tampering | AppStream nodejs module (EL9) | low | mitigate | `nodesource_module_reset` (rhel) defuses the AppStream module so the NodeSource repo wins (Pitfall 4) — otherwise the wrong (older) Node could be installed. |
| T-57-SC | Tampering | crates.io installs (no new crates) | low | accept | No new dependencies this plan. |
</threat_model>
