<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sudoers content → `/etc/sudoers.d/agentlinux` | A malformed sudoers drop-in would lock out sudo host-wide (DoS); the visudo `-cf` gate before install + re-verify after (TOCTOU belt) bounds this. |
| install-user name → the NOPASSWD line | The user name flows into a privilege grant; it is charset-validated upstream (57-02) so a crafted name cannot inject sudoers syntax. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-57-07 | Denial of Service | `/etc/sudoers.d/agentlinux` | high | mitigate | visudo `-cf` validates the tmpfile BEFORE the atomic 0440 install AND re-verifies the installed file after (TOCTOU belt) — a malformed sudoers can never land and lock out the host. Task 1 asserts the two visudo calls. |
| T-57-08 | Elevation | the NOPASSWD grant line | high | mitigate | The install-user name is charset-validated (`^[a-z][a-z0-9_-]*$`) upstream (57-02) before it reaches the sudoers line, so a crafted name cannot inject extra sudoers directives; the grant scope is the documented ADR-012 `ALL=(ALL) NOPASSWD: ALL`. |
| T-57-SC | Tampering | crates.io installs (no new crates) | low | accept | No new dependencies this plan. |
</threat_model>
